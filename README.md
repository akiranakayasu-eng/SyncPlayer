# SyncPlayer v0

10 台ほどの Mac で同じ映像を同期再生する試作。各 Mac が手元のファイルを再生し、有線 LAN の UDP だけで合わせる。

## しくみ

1. 時計合わせ: フォロワーがマスターに往復の問い合わせを送り、往復が一番短かった回から「マスターの時計 − 自分の時計」を出す（NTP と同じ考え）。
2. 開始の予約: マスターは「マスターの時計で T に、映像の P 秒から再生」と 0.2 秒おきに知らせる。各 Mac は自分の時計に直して `AVPlayer.setRate(_:time:atHostTime:)` で予約再生する。
3. ずれの微調整: 0.05 秒おきに、今の再生位置と予定の位置を比べ、速さを最大 ±1% 上げ下げする。40 ms を超えてずれたら予約し直す。

## 使い方

テスト映像（60fps・20 秒・フレーム番号入り）は `tools/make-test-video.sh` で作る（ffmpeg が要る）。

```
tools/make-test-video.sh
swift build -c release
.build/release/SyncPlayer --master   sync-test-60fps-20s.mp4 --log
.build/release/SyncPlayer --follower sync-test-60fps-20s.mp4 --log --name B
```

キー: スペース 再生／停止（マスター）、r 頭へ、← → 5 秒、i 情報、f 全画面、q 終了。
ポート: UDP 47800（知らせ）、47801（時計）。同じ Mac でフォロワーを何個でも起動できる。マスターは 1 台に 1 つ。

## 既知の制限（v0）

- ループの継ぎ目で一瞬（約 0.1 秒）止まる。
- 同期の精度はプレイヤー自身が測った再生位置の差（Air 1 台で 3 つ起動して平均 0.1〜0.2 ms）。画面に出るまでの差は別に、カメラで測る必要がある。
- ディスプレイの描画タイミングは揃わないので、最大 1 フレームの差は残る。
- 素材はフレーム間圧縮の少ないもの（ProRes、HAP、H.264 の全フレームキー）を推奨。飛び先の読み込みが遅いと予約に間に合わない。
