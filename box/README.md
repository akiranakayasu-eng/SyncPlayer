# SyncBox（Raspberry Pi 用の再生の箱、試作 段 1）

Raspberry Pi 5 を、SyncPlayer の Mac といっしょに同期再生する「箱」にするソフト。電源を入れると、映像を 1 本全画面でループ再生し、同じ LAN の SyncPlayer に合わせる。Mac と箱を 1 つの展示に混ぜられる。箱どうしだけでも動く（どれか 1 台をマスターにする）。

- 同期の知らせは Mac の SyncPlayer とまったく同じ（UDP 47800・47801、時計合わせ、開始の予約、共通のループ）。つなぐ Mac は v0.3.0 以降にする。
- 再生は mpv に任せ、`syncbox.py`（Python の標準だけで書いた 1 ファイル）が mpv を操って時間を合わせる。
- 段 1 でできるのは、映像 1 本・全画面・ループ・フォロワーかマスター・電源を入れると始まる、まで。レイヤー・四隅・メッシュ（段 2）、照明（段 3）、箱の Web 画面・ボタン（段 4）はこれから。

## 用意するもの

| もの | 目安（税込） |
| --- | --- |
| Raspberry Pi 5 / 4GB | 22,990 円 |
| 公式ケース（ファン付き） | 2,200 円 |
| 27W USB-C 電源（公式） | 2,000 円前後 |
| microSD 32GB（できれば工業用） | 1,000〜3,000 円 |
| micro HDMI → HDMI ケーブル | 1,000 円前後 |
| LAN ケーブル（同期は有線をすすめる） | — |

## 入れ方

1. Raspberry Pi Imager で microSD に **Raspberry Pi OS Lite（64-bit）** を書く。設定の画面でユーザー名、SSH を入れる、ホスト名（例 `box-1`）を決めておく。
2. 箱を起動し、Mac からこのフォルダを写して入れる。

   ```sh
   scp -r box box-1.local:
   ssh box-1.local 'sudo sh box/install.sh'
   ```

3. 映像を HEVC（H.265）に変えて、箱の `~/syncbox/` に写す。Pi 5 が回路で解けるのは HEVC だけ（H.264 は CPU で解くので重い）。

   ```sh
   ffmpeg -i 元の映像.mov -c:v libx265 -crf 20 -preset medium -g 30 -pix_fmt yuv420p -tag:v hvc1 -an movie.mp4
   scp movie.mp4 box-1.local:syncbox/
   ```

4. `~/syncbox/syncbox.json` を直して再起動する（`sudo systemctl restart syncbox`）。以後は電源を入れるだけで始まる。

## 設定（syncbox.json）

| 項目 | 意味 |
| --- | --- |
| `movie` | 映像のファイル（このファイルからの相対でよい） |
| `role` | `follower`（標準、マスターに合わせる）か `master` |
| `name` | 名前（マスターのとき Mac の札に出る） |
| `autoplay` | マスターのとき、起動したら再生する（標準 true） |
| `loop` | マスターのとき、共通のループの長さを秒で決める（0 は自動: 全台で一番長い映像） |
| `ownLoop` | マスターのとき、true にすると映像ごとに自分の長さでループ |
| `audio` | 映像の音を出す（標準 false） |
| `broadcast` / `to` | マスターのとき、知らせを送る先（ブロードキャストが通らない LAN では `to` に相手の番地を並べる） |
| `log` | 1 秒ごとにずれ・速さ・往復時間を出す（`journalctl -u syncbox -f` で見る） |
| `mpvArgs` | mpv に渡すオプション（画面の出し方・ハードでの復号） |

コマンドでも同じことができる: `python3 syncbox.py movie.mp4 --master --log`。

## 時間の合わせ方

- 時計合わせと予定は Mac と同じ（[README のしくみ](../README.md#しくみ)）。
- mpv には「この時刻に再生を始める」呼び出しが無いので、頭出しは「少し先へ飛んで止め、その時刻に再生を始める」で行う（0.5 秒先）。
- 走り出したあとは 0.05 秒ごとに再生位置と予定を比べ、ならしたずれが 4 ms を超えたら速さを 0.95〜1.05 倍の間で少し変えて戻す（mpv は速さを変えても止まらない）。1 回でも 0.25 秒を超えたら頭出しし直す。
- mpv が返す再生位置は表示中のコマの時刻なので、半コマぶん足して比べる（`--pos-bias` で変えられる）。
- 共通のループが自分の映像と同じ長さのときは mpv がそのままループする。長いときは最後のコマで止めて待ち、ループの点の 0.2 秒前に頭のコマを出して、その時刻に再生を始める。

## 試し方（Mac も箱も無いところで）

```sh
python3 -m unittest box/test_syncbox.py
```

仮の再生器と仮の時計で、頭出し・時計の差・速さの直し・ループ・最後のコマで待つ・止める／飛ぶ、と、同じ機械の中でのマスターとフォロワーのやりとりを確かめる。`fake_mpv.py` は mpv の代わりに IPC に答えるだけの試験用（画面は出ない）。

## 実機で確かめること（段 1）

1. Pi 5 で HEVC 1080p と 4K がハードで解けて、コマ落ちなく出るか（`mpvArgs` の `--hwdec` が効いているか）。
2. Mac（マスター）＋箱（フォロワー）で、`log` のずれ（mean）が数 ms 以内に落ち着くか、速さの直しが続かないか。
3. 箱がマスター、Mac がフォロワーでも合うか（Mac の札にマスターの名前が出るか）。
4. 2 台を並べてカメラで撮り、画面のずれが 1 コマ以内か。
5. mpv 自身のループの継ぎ目で止まりやすくないか、継ぎ目のあとにずれが残らないか。
6. 共通のループが長いとき、最後のコマで待って頭から合うか。
7. 電源を抜いて入れ直すと、自動で始まって合うか。
